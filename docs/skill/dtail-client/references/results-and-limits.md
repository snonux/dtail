# Interactive control, results, and limits

## Reload a live session

Add `--interactive-query` to `dcat`, `dgrep`, `dtail`, or `dmap` when a controlling TTY exists. The TTY accepts `:show`, `:help`, `:reload <flags>`, and `:quit`. The initial workload can run on an older server, but live reload requires `query-update-v1` on every active connection; a rejected reload leaves the current workload running. A successful reload reuses SSH sessions and drops late output from the prior workload.

`:reload` accepts `--files`, `--plain`, `--quiet`, and `--timeout` for all modes. `dgrep` and grep-driven `dtail` also accept `--grep`/`--regex`, `--invert`, `--before`, `--after`, and `--max`; `dmap` and query-driven `dtail` accept `--query`. Flags omitted on reload retain their values. `--invert=false` clears a previous inversion. Each reload needs at least one flag and must retain nonblank files and, in query mode, a nonblank query. An empty `--regex ''` selects every line in a reload unless inversion remains on; `:reload --grep ''` is rejected. Quote a path or regex with spaces as on a shell command line; reload tokenization does not expand variables, commands, or globs. See `doc/interactive-query.md` for its exact quoting rules.

## Interpret output and status

- Standard remote output prefixes lines with source information such as `REMOTE|host|...`; `--plain` emits payload without that framing. `--noColor` suppresses terminal color. With current client and dserver versions, control-frame negotiation keeps payload lines like `.syn close connection` or `AUTHKEY OK` intact in plain mode; an older counterpart can misinterpret or drop them.
- Default `fout` logging sends payload to stdout and writes diagnostics to `~/log/YYYYMMDD.log`; it does **not** copy payload into that file. `--log-payload` or `Client.LogPayload` opts in to the copy. `--logger stdout` uses stdout only, `--logger none` disables the logger, and `--logger file` uses a file sink, including payload. Explicit `--logger`/`--logDir` beats `Common.Logger`/`Common.LogDir`, which beat command defaults. In server mode, dserver warnings appear in client output even at a restrictive client log level; with `--plain`, a `WARN|...` line can be mixed into redirected payload. Serverless warnings use the client's logger and are filtered by its log level (default `warn`).
- `dcat` and `dgrep`: `0` means the sessions completed (including a `dgrep` search with no match); `1` means connection, setup, unsupported capability, or truncated-session failure; `2` means an invalid flag or a server-reported command failure such as missing/denied/unreadable input, glob cap, malformed read, or output-buffer overflow. The highest status among servers wins. Partial output can precede a nonzero status. Servers older than `command-failure-v1` can return `0` for missing input.
- `dtail` follows and reconnects, so its status does not signal every failed read. `dmap` may write the received partial result and exit `0` after a reported incomplete result or interrupted session; check its WARN diagnostics before treating its outfile as complete. Scheduled and continuous MapReduce jobs have separate failure behavior described in `doc/server-configuration.md`. `dtailhealth` prints `OK` (`0`), `WARNING` (`1`, including serverless mode), or `CRITICAL` (`2`).

## Compatibility and source boundaries

- Remote `journal:` reads require `journal-v1`. Remote paths with interior spaces or a `base64%` prefix require `encoded-read-path-v1`. A reload checks all active servers before changing any of them. Source paths containing commas or leading/trailing blanks cannot be represented by `--files`.
- A remote file or journal target is checked against dserver permissions and OS access. A missing path, empty glob, or capped glob can make a result incomplete. Long lines may be split at `Server.MaxLineLength` with a warning. Compression support depends on the dserver build.
- For a result intended to be machine-readable, use `--plain --logger stdout` and still account for server warnings and exit status. When exact bytes matter, verify the data stream and source conditions; `dcat --plain` in serverless mode can reproduce a regular file, while server-mode warnings can enter stdout.
